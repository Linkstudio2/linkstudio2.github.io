01 项目概述

《归山录》是一款以“归山”意象为核心的原创游戏策划项目。项目尝试把家园经营、资源采集、炼丹锻造、探索任务与回合制战棋战斗串成一条可持续的成长体验：玩家在山中生活，积累资源，理解人物与地域关系，再带着准备好的物资进入更高风险的探索。

项目项内容
项目名称《归山录》
项目类型原创个人项目；融合家园生活、探索、任务与回合制战棋设想

当前阶段已有 Demo 语境与 UI 改版需求；完整系统仍处于方案与规划阶段
作品集目标展示需求拆解、玩法设计、状态管理、视觉沟通和迭代复盘能力

项目状态口径

“已完成 Demo”只用于描述当前上下文中明确出现的 Demo 成果；“已提出方案”用于描述已经形成设计意图或规则草案的内容；“未实现规划”用于描述尚未进入可运行版本的系统、资产和后续验证项。

02 项目定位与核心体验

项目定位是“慢节奏山居生活”与“有准备的策略冒险”的结合。生活部分提供稳定、可重复的节奏，探索部分提供不确定性和风险，战斗则把准备过程转化为可决策的回合结果。核心体验可以概括为：采集与制作让我更了解这座山，探索与战斗让我承担选择的代价，回到家园让我看到成长被留下。

体验目标设计回应状态
有节奏的山居日常将种田、采药、炼丹、锻造拆成可独立验证的日常行为，并通过资源回流连接探索。已提出方案
准备感与决策感让出发前的装备、药品、队伍或路线选择影响探索结果。已提出方案
人物关系带来的记忆点以 NPC 任务、委托和地域事件承载人物动机与世界信息。已提出方案
清晰、可读的操作界面围绕状态、资源、行动和反馈重做 UI 层级，降低理解成本。已提出方案

03 世界观与玩法循环

世界观表达方向

世界观暂以“山中归隐、人与自然共生、旧事在日常中重新显影”为叙事基调。设计上不依赖大段设定说明，而是把信息拆到物品描述、NPC 任务、地形变化、配方来源和战斗遭遇中，让玩家通过行动逐渐拼出这座山的过去。该部分目前属于世界观与叙事方向，尚未宣称已有完整剧情文本或关卡落地。

核心玩法循环

阶段玩家行为获得的反馈状态
生活种植、采药、整理仓库、制作物品资源增长、配方解锁、家园状态变化已提出方案
准备选择药品、装备、队伍和探索目标风险可预期，形成出发前策略已提出方案
探索移动、调查、接取任务、遭遇事件获得材料、信息和人物关系推进已提出方案
战斗在回合制战棋中安排站位与行动战术结果、消耗与战利品已提出方案
回家交付任务、使用资源、调整下一轮计划长期成长和情绪回收未实现规划

策划重点是让每个环节都产生下一环节需要的输入，避免生活、探索和战斗成为彼此孤立的模块。

04 家园生活系统

家园系统承担“稳定产出、低压力试错、长期成长”的功能。设计时优先考虑操作成本和反馈清晰度：玩家应能快速知道今天能做什么、资源从哪里来、制作后能解决什么问题。

子系统功能定义关键规则草案状态
种田提供稳定的基础材料与时间安排作物有生长周期；种植地块、季节或天气可作为后续扩展变量已提出方案
采药把探索和生活连接起来药材按区域与稀有度分布；部分材料需要特定工具或时段已提出方案
炼丹把采集材料转化为战斗准备配方由材料组合决定效果；失败或低品质结果可作为风险与学习反馈已提出方案
锻造提供装备成长与构筑差异装备以部位、词条或材料特性形成选择；优先保证可读性和可替换性已提出方案
家园信息承载库存、制作、状态和升级反馈采用统一资源分类、明确数量和来源提示未实现规划

策划关注点

把资源分为“基础材料—加工材料—战斗消耗—任务物品”，减少玩家记忆负担。

让每种生活行为都有明确用途：种田负责稳定供给，采药连接探索，炼丹服务战斗，锻造形成长期成长。

控制日常操作的重复成本，优先验证一次完整循环是否有满足感，再扩展内容量。

05 探索与 NPC 任务

探索系统是连接家园和叙事的中段体验。设计目标不是单纯扩大地图，而是让玩家带着问题出发，并在路线、资源和人物选择中形成记忆。NPC 任务应同时承担三项功能：提供目标、解释世界、推动关系变化。

任务结构设计意图示例表现状态
委托型任务给出清晰目标，帮助玩家熟悉系统寻找药材、制作物品、护送或调查已提出方案
关系型任务让 NPC 的需求和玩家选择产生后果选择交付对象、保留材料或改变路线已提出方案
探索型事件让地图内容具有偶发性和发现感路遇遗迹、天气变化、隐藏采集点未实现规划
任务回收把结果带回家园并形成下一轮计划奖励配方、材料、线索或家园变化未实现规划

06 回合制战棋战斗设计

战斗系统定位为“低频但有分量”的策略环节：玩家通过前置准备降低风险，通过站位和行动顺序处理当下局面。由于当前上下文未提供可核验的战斗 Demo 细节，本节以设计方案记录，不将规则描述为已实现功能。

设计层方案内容验证问题状态
棋盘与移动以格子或明确区域表达移动范围、阻挡与地形效果地图尺寸是否让决策有空间但不拖沓？已提出方案
行动顺序采用回合或行动条式的明确顺序玩家能否在行动前预测敌我反应？已提出方案
角色定位通过攻击、保护、控制、支援等职责形成组合不同角色是否有不可替代的使用场景？已提出方案
资源消耗把药品、技能或装备耐久纳入出发前准备消耗是否带来决策而非单纯惩罚？未实现规划
战斗反馈强化命中、受击、状态变化和回合结束信息反馈能否帮助玩家复盘选择？未实现规划

07 UI UX 与美术规范

UI 改版是当前对话中明确提出的方向之一。策划侧的重点不是单独追求装饰效果，而是把界面信息分层，让玩家在“我现在处于什么状态、下一步可以做什么、这次行动会付出什么”三个问题上快速得到答案。

信息架构

界面层级应承载的信息改版原则状态
全局 HUD时间、地点、核心资源、当前目标只保留高频信息；避免把所有系统入口同时铺开已提出方案
家园界面地块、制作、库存、升级入口以行为为中心组织入口，减少跳转层级已提出方案
探索界面路线、事件、队伍状态、可交互对象强调可读地图与下一步行动提示已提出方案
战斗界面行动顺序、移动范围、技能、状态效果先让玩家看懂局面，再提供操作选项已提出方案
反馈层获得、消耗、解锁、失败原因所有关键变化都给出来源和结果未实现规划

视觉规范方向

色彩：以山林、土壤、药草和旧纸张为灵感，建立低饱和主色与高对比状态色。

形状：用圆角、木牌、纸张或器物边角表达生活感，但保持按钮、标签和状态图标的识别优先级。

字体与图标：优先保证小字号可读、状态图标可区分、数字与单位排列稳定。

反馈：点击、获得、失败、解锁等操作需要统一的动效和音效语义，避免每个模块各自表达。

08 视觉与音频方向

视觉与音频部分目前应作为制作规范与沟通参考，不表述为已经完成的美术资产或音乐成品。策划需要把“想要的感觉”翻译成制作团队可以执行的约束。

方向策划描述可交付物状态
场景氛围安静、克制、带有季节和天气变化的山居环境场景关键词、色彩板、参考图分组未实现规划
角色与 NPC通过服饰、道具和动作区分职业、关系与生活状态角色功能表、立绘需求、动作清单未实现规划
UI 视觉自然材料质感与清晰信息层级并存UI 组件清单、页面线框、状态规范已提出方案
音频环境声建立空间，交互声强化操作反馈，战斗声突出结果音频事件表、情绪关键词、优先级未实现规划

09 MVP 与开发优先级

MVP 的目标是验证“生活准备—短程探索—结果回家”是否形成闭环，而不是一次性实现所有内容。优先级按验证价值和依赖关系排序。

优先级范围验收标准状态
P0基础移动、家园入口、基础采集、单条探索路线、最小任务反馈玩家能完成一次从家园出发、获得资源、回家结算的完整循环未实现规划
P1基础制作、两类消耗品、简单战斗原型、资源与任务 UI玩家能感受到准备行为对探索/战斗结果的影响未实现规划
P2NPC 关系、更多配方、地形效果、UI 视觉统一系统间连接增强，重复游玩仍有选择空间未实现规划
P3天气、季节、隐藏事件、音频完整化、内容扩展形成更稳定的长期内容框架未实现规划

在求职作品中，MVP 表现了我会先定义验证目标，再拆解依赖和验收标准，而不是直接堆叠功能列表。

10 与 Codex 协作的迭代方法

在项目实践中，我把 Codex 视为可执行的协作对象：先提供清晰目标和约束，再通过截图、运行结果与问题清单进行多轮修正。该方法适用于 UI 改版和小型玩法原型的快速迭代。

步骤我的策划动作产出
1. 定义目标说明玩家问题、页面用途、必须保留的信息和验收标准需求说明与优先级
2. 提供参考整理视觉关键词、布局参考、状态样例和不可变约束参考图清单、组件说明
3. 拆分实现把页面或系统拆成可独立验证的小任务任务卡与完成条件
4. 运行检查观察可读性、操作路径、状态反馈和异常情况问题记录与修改建议
5. 复盘沉淀把有效做法整理为规范，减少下一轮沟通成本UI 规范、系统规则、版本记录

沟通时我会把“感觉不好看”改写成可执行的问题，例如“核心资源与当前目标的视觉层级不够明显”“交互后的结果没有在同一视线范围内反馈”“按钮状态无法区分可用与不可用”。

11 个人职责与复盘

个人职责

项目定位与核心体验提炼：把“山居生活 + 冒险”转化为可讨论的体验目标。

系统策划：拆解家园、制作、探索、任务与战斗之间的输入输出关系。

视觉参考分析：提出 UI 信息架构、视觉方向和状态反馈规范。

需求沟通与迭代：向 Codex 描述目标、约束、验收标准，并基于运行结果修正。

作品整理：将方案、状态和后续计划整理为可供他人理解的策划文档。

复盘

复盘问题当前认识下一步改进
是否先验证核心循环？系统设想容易扩张，MVP 必须先验证一次完整循环。先做最小闭环，再加入关系、天气和内容扩展。
是否把状态说清楚？作品集若不区分完成与规划，容易造成误解。在需求、版本和展示材料中统一使用状态标签。
是否把审美转成规则？视觉描述需要落到层级、颜色、组件和反馈。建立 UI 组件清单和页面验收表。
是否能让他人接手？单独想法不能直接转化为开发输入。补充流程图、字段定义、异常分支和验收标准。

12 后续规划

下一阶段将围绕“可运行验证”推进，而不是继续扩写世界观。计划先完成一个小范围垂直切片：一个家园区域、一个采集行为、一条探索路线、一个 NPC 任务和一个最小战斗场景。通过这条切片检查资源流转、任务反馈、UI 可读性与玩家节奏，再决定是否扩大内容量。

阶段目标关键产出状态
阶段一完成闭环原型家园—探索—回家结算的可运行流程未实现规划
阶段二验证战斗与制作的连接基础装备/药品对战斗结果产生可感知影响未实现规划
阶段三统一 UI 与反馈核心页面、状态、动效和音频语义统一未实现规划
阶段四扩展内容并测试NPC 任务、地图事件和重复游玩验证未实现规划

结语

《归山录》目前更适合作为一份持续迭代中的策划案例：它展示了我如何从体验目标出发，拆解系统、组织状态、提出视觉规范，并与执行工具进行多轮沟通。对游戏策划实习岗位而言，我希望通过这份作品呈现的重点是问题意识、结构化表达和把方案推进到可验证阶段的能力。
